# Historical Audit Intelligence

Historical Audit Intelligence is a defensive supporting-evidence layer for Ethereum DeFi Risk Radar. It uses a locally prepared corpus of historical smart-contract audit findings to add context to findings produced by verified-source analysis.

It deliberately does **not** turn historical similarity into a vulnerability or exploitability verdict.

## Three-stage design

### Stage 1 — Development dataset

`npm run audit:prepare` downloads or reads the Zaevlad smart-contract audit CSV, validates the schema, cleans records, removes duplicate title/description records, normalizes severity, strips researcher attribution from titles, assigns a deterministic vulnerability taxonomy, recomputes a quality score, and creates a deterministic 80/20 train/benchmark split.

The cleaner deliberately drops proof-of-concept code. The runtime corpus stores only `hasPoc: boolean`; it never stores PoC/exploit text for Historical Audit Intelligence.

Default output:

```text
~/.defi-risk-radar/audit-intelligence/
  cleaned-audit-findings.jsonl
  audit-benchmark.jsonl
  audit-dataset-stats.json
  audit-evaluation.json
```

Use a local file instead of downloading:

```bash
npm run audit:prepare -- --source=/path/to/bug_list.csv
```

Use another output directory:

```bash
npm run audit:prepare -- --output=/path/to/audit-intelligence
```

Runtime can use a different cleaned corpus with:

```bash
RISK_RADAR_AUDIT_CORPUS=/path/to/cleaned-audit-findings.jsonl
```

### Stage 2 — Historical Audit Intelligence

When verified Solidity source produces a source or advanced structural finding, the local intelligence engine:

1. classifies the current finding into the audit taxonomy;
2. retrieves historically similar audit findings using a bounded TF-IDF/cosine index;
3. calculates the weighted historical severity distribution;
4. derives a historical review-priority score from similarity, analogue severity, corpus quality and classifier confidence;
5. collects common historical remediation text; and
6. attaches the context to the existing finding description and to the structured `historicalIntelligence` object on `SourceInspection`.

The existing Source Findings screen therefore receives historical context without requiring a second vulnerability verdict or bypassing Risk Radar's evidence model.

### Stage 3 — Local statistical models and evaluation

The runtime trains a dependency-free multinomial Naive Bayes category classifier over the local cleaned corpus and uses the same corpus to construct a TF-IDF similarity index. The dataset cleaner executes deterministic holdout evaluation and writes `audit-evaluation.json`.

Reported evaluation fields include:

- category accuracy;
- macro F1;
- top-5 same-category retrieval hit rate;
- mean classifier confidence; and
- benchmark coverage.

These are **internal-consistency / retrieval-utility metrics**, not vulnerability-detection accuracy. The benchmark taxonomy labels are generated by the cleaning rules rather than independently adjudicated human ground truth.

## Taxonomy

The first version includes:

- reentrancy;
- access control;
- oracle/price;
- accounting/state;
- precision/rounding;
- token integration;
- signature/replay;
- upgradeability;
- denial of service;
- MEV/front-running;
- governance;
- bridge/cross-chain;
- liquidation;
- flash liquidity;
- input validation;
- gas/economic;
- business logic; and
- other.

Verified-source review rules were also expanded with audit-derived surfaces for token accounting, permit/nonces, cross-chain messaging, liquidation/solvency and MEV/slippage.

## Evidence semantics

Historical intelligence is intentionally lower authority than executed/reproduced evidence.

```text
Public lead
  -> verified Mainnet source
  -> native/optional analyzer finding
  -> historical analogue context
  -> optional executed counterexample
  -> optional deterministic replay
```

Historical similarity never upgrades `HEURISTIC`/`STRUCTURAL` evidence to `EXECUTED` or `REPRODUCED`, and the historical review-priority score must never be displayed as an exploitability percentage.

## Dataset licensing boundary

The Zaevlad dataset card currently declares `license: other` and states that licensing/authorship of underlying third-party audit reports is unclear. Risk Radar therefore:

- does not commit the source dataset;
- does not bundle the cleaned dataset in Windows/macOS installers;
- writes prepared corpora only to the user's local machine;
- records `licenseStatus: UNVERIFIED_THIRD_PARTY` and `redistributionAllowed: false` in metadata; and
- keeps generated corpus files in `.gitignore`.

Resolve provenance and redistribution/commercial-use rights before shipping any third-party records or a model whose distribution depends on those rights.

## Verification

Run:

```bash
npm run check
npm run test:audit-intelligence
```

The audit-intelligence regression check covers cleaning, title attribution removal, placeholder PoC handling, taxonomy assignment, local classifier/retrieval behavior, bounded historical risk scores, no PoC exposure, license metadata, verified-source integration, and evaluation semantics.
